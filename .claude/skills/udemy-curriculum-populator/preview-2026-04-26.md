## Gaps surfaced by the live preview

### Gap 1 — DOM model is FLAT, not nested (CRITICAL playbook fix)

The original playbook said "for each section, find lecture rows nested inside `[data-purpose="section-editor"]`." That's wrong. Sections and lectures are SIBLINGS in `[data-purpose="curriculum-list"]`, each wrapped in `div.js-curriculum-item-draggable.curriculum-list--list-item--xn0`. To find lectures belonging to a section, walk siblings forward from the section-editor wrapper and group consecutive `lecture-editor` wrappers until the next `section-editor` wrapper.

### Gap 2 — Lecture row + title selectors now CONFIRMED (was TBD)

| Element | Selector |
|---|---|
| Lecture row | `[data-purpose="lecture-editor"]` |
| Lecture/section title text | `[data-purpose="item-full-title"]` (innerText starts with `"Section N:"` or `"Lecture N:"` — strip prefix) |
| Lecture/section index/order | `[data-purpose="item-object-index"]` (innerText is `"Section N:"` or `"Lecture N:"`) |
| Lecture edit button | `[data-purpose="lecture-edit-btn"]` |
| Lecture delete button (DO NOT auto-click) | `[data-purpose="lecture-delete-btn"]` |
| Lecture collapse toggle | `[data-purpose="lecture-collapse-btn"]` |
| Edit-content wrapper | `[data-purpose="edit-content-wrapper"]` |
| Inline edit-content area | `[data-purpose="edit-content"]` |

### Gap 3 — Demo sections (8-11) have no `### Lectures` block

The current parsing rule says lectures only come from N.M lines under `### Lectures`. Sections 8-11 in this course's outline are demos — they document a single walkthrough but don't list lectures. The populator would CREATE the 4 sections with zero lectures. The user must then either (a) accept that the demo walkthrough is the section itself (no lecture stub) and upload the recording at section level, OR (b) manually add a 1-lecture stub per demo section in the dashboard.

**Proposed playbook patch:** Add a parsing rule for sections matching `/^## Section N: Demo \d+ — /` — auto-generate a single planned lecture titled `Demo Walkthrough` so each demo section gets a 1-lecture stub. Or surface as a deliberate user prompt at preview time.

### Gap 4 — Section→folder mapping for `section-overview.md` lookup

The course-outline.md filesystem note documents a legacy section→folder mismatch:

| Outline section | Filesystem folder |
|---|---|
| Section 4 | `scripts/section-05-claude-code-config/` |
| Section 5 | `scripts/section-06-prompt-engineering/` |
| Section 6 | `scripts/section-04-tool-design-mcp/` |

The playbook says "try to read `scripts/section-NN-<slug>/section-overview.md`" but uses the section NUMBER for `NN`. For sections 4-6 in this course, that lookup misses. **Proposed playbook patch:** lookup by section title (kebab-case keyword match) against folder names rather than by zero-padded number. Or read the filesystem note from `course-outline.md` if present.

### Gap 5 — Existing placeholder data on Section 1 + Lecture 1.1

The dashboard has Udemy's auto-generated `"Introduction"` placeholder for both. The populator's title-mismatch behavior (additive only — surface diff, don't modify) is correct for safety but means the user has two manual cleanup options:

2. Delete Section 1 in the dashboard, then re-run — populator creates fresh

The playbook should call this out in the worked example.
